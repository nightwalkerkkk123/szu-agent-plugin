## Friction

- **Context-stale**: WORKING-CONTEXT.md at the start of this session still
  listed proposal/demo.sh/grep-evidence as "待创建", even though some were
  in flight. A snapshot taken at session start would have been more
  honest. → Refreshed at end-of-session. Lesson: take a fresh snapshot
  at end of each phase, not at arbitrary points.

- **Tool-broken (logback)**: Maven Shade relocated `ch.qos.logback.*`
  classes but **not** `logback.xml` resource. `RollingFileAppender` and
  `LogbackContextSelector` failed at startup with `ClassNotFoundException`.
  Root cause: shade plugin rewrites class refs, not resource files.
  **Fix**: remove logback + slf4j relocations; keep only Jackson. Static
  guard `LogbackShadeConsistencyTest` parses pom.xml and asserts no
  relocation pattern overlaps with logback. Lesson: shaded plugins need
  either relocate-everything (incl. resources via `filters`) or
  relocate-nothing for that classpath.

- **Pattern-unclear (5 vs 4)**: Proposal originally listed 5 patterns
  including Command (picocli) and Pipeline (architecture). Code had
  5 `// Design Pattern:` annotations matching the proposal, but ADR-0007
  D1 had committed to 4. Realigned by deleting the Command annotations
  rather than drafting ADR-0008 — code should match the committed
  decision, not the other way around. Lesson: always run `grep` for
  declared contracts before writing evidence docs; the discrepancy
  surfaces immediately.

- **Annotation drift (泛型)**: When writing grep-evidence.md I noticed
  `Matcher.java` and `RetryPolicy.java` (both core泛型 interfaces) had
  the `// 编程技术:` line saying `@FunctionalInterface` but not `泛型`.
  The grep count (1 file for 泛型) didn't match the proposal claim of
  "multiple". Fixed the annotations to be honest. Lesson: evidence
  tables expose annotation drift; write them early as part of the
  TDD loop on documentation.

- **Other (push permission)**: `git push origin master` failed —
  `Permission denied to Autur-wang`. SSH key fingerprint maps to a
  different GitHub account, not the repo owner `nightwalkerkkk123`.
  Local master is fast-forward compatible; user must push from a shell
  with the correct SSH key. Documented in WORKING-CONTEXT.md "下一步".

## Harness Improvement

**Pain:** Annotation drift (`// 编程技术:` lines not enumerating all
techniques actually used) was caught only at the grep-evidence step,
not when the code was first written.

**Proposal:** Add a `docs/annotations.md` "checklist" that pairs each
of the 4 patterns and 6 techniques with a 1-line reminder of where it
**should** appear. CI could grep for missing entries by
package/technique matrix. Lower-effort version: a pre-commit hook
that runs `scripts/grep-runs.sh` (already exists) and blocks commit
on drift.

## Decisions Made

- **D1**: Drop `// Design Pattern: Command` annotations from
  `BookingCommand.java` and `VenueCommand.java` per ADR-0007 D1.
  picocli is a framework, not a project-level GoF pattern. Replaced
  with a Javadoc note pointing at ADR-0007.

- **D2**: Keep Pipeline as an "architecture note" in proposal §3.5,
  not as a 5th pattern. 7-step `BookingStep` chain is Strategy
  applied at scale; introducing a 5th pattern would require ADR-0008.

- **D3**: Annotation visibility relaxation on `VenueCommand.parseTimeSlot`
  and `VenueCommand.exitCodeFor` from `private` to package-private
  static. Trade-off: slightly looser encapsulation in exchange for
  direct unit-test access. The two methods have no observable side
  effects (pure functions on inputs).

- **D4**: `scripts/demo.sh` writes a timestamped log to `logs/`
  directory on each run. Lets the user post-mortem demo failures
  without needing to rerun. Log file path is in the final summary
  output.

- **D5**: `scripts/grep-runs.sh` exits 1 on count drift, prints the
  drift file list. This makes it a static guard, not just a one-shot
  script — running it in CI keeps evidence honest.
