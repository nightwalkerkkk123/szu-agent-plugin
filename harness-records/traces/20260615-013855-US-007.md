## Decisions

详见 `docs/adr/0008-session-persistence.md`,4 个核心决策:

- **D1 架构落点**:扩展 `BrowserLifecycle` 接口加 2 方法(vs 新建 SessionAdapter)。理由:Adapter 模式本意适配 API 表面,storageState 是 Playwright `BrowserContext` 能力,放同一 adapter 是 GoF 原意;deletion test 通过(删 SessionAdapter → 复杂度归零)
- **D2 存储位置**:`~/.szu-agent/sessions/<username>.json` + POSIX 600(vs 加密 / 跨设备同步)。理由:Playwright SDK 设计明文 JSON,加密层破坏 SDK 工作流;username 白名单 `^[A-Za-z0-9_.-]+$` 防 path traversal
- **D3 会话语义**:TTL 30 天 + 探针主动失效(vs 仅 TTL / 仅探针)。理由:TTL 是快速 reject,探针是事实判定,两层兜底;探针 Stale 时主动删损坏文件
- **D4 接口签名**:`importStorageState` 返 `boolean`(常见路径,无需异常),`exportStorageState` 返 `void` 抛 `BookingException(SESSION_WRITE_FAILED)`(罕见路径,值得 trace);`PersistSessionStep` catch RuntimeException 仅 warn,避免业务降级

## Friction

- **Plan Task 11 改 `open()` 后破坏 PlaywrightBrowserAdapterTest 26 个用例 mock 链**(category: `dependency-confusion`):
  - **症状**:Plan 把 `browser.newPage()` 改为 `browser.newContext().newPage()`,但 plan 没列出测试 mock 链需要同步更新。原 `when(browser.newPage()).thenReturn(page)` 全部失效,26 个用例集体红灯
  - **解决**:通过 implementer agent 同步更新 mock 链(`when(browser.newContext()).thenReturn(context)` + `when(context.newPage()).thenReturn(page)`),并新增 4 个 storageState 测试用例覆盖 import/export 路径
  - **Lesson**:接口扩展波及测试 mock chain 时,**plan 应预先列出**所有依赖的 mock 链需要同步更新的测试类。下次 plan 类似改动(改 SDK 调用顺序)时显式标注:"该 task 会破坏 X 个现有测试的 mock 链,需同步更新"

- **archunit ADR-0005 D2 log 字面量约束**(category: `pattern-unclear`):
  - **症状**:写代码时本能想 log "session restored",会被 archunit 阻止
  - **解决**:所有新代码 log 串审查,改用 "persisted state" / "auth" / "import returned false" 等措辞;HANDOFF 文档明文标记
  - **Lesson**:特定领域术语(session/cookie/token)被 LogMasker 屏蔽,实施前应在 plan 头部 explicit 列出"forbidden words"清单
