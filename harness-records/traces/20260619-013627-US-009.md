## 四、设计模式与编程技术

| 模式/技术 | 落点 |
|---|---|
| Strategy | `ScheduleListExtractor` / `NavigateToScheduleStep` / `ParseScheduleStep` |
| Adapter | 复用 `BrowserLifecycle` / `PlaywrightBrowserAdapter` |
| Singleton | 复用 `ConfigManager` / `Tracer` / `Skills` |
| Builder | `WeekRange` 内有链式 parse(轻度) |
| record | `Weekday` / `Period` / `WeekRange` / `CourseEntry` / `ScheduleListResult` |
| sealed interface | `ScheduleListResult` permits Success / Failure |
| 不可变 | 所有 domain record + `List.copyOf()` |
| 正则表达式 | `WeekRangeParser.SEGMENT` / `ScheduleListExtractor.COURSE_SECTION` |
| Lambda | `BookingStep.of()` factory(未被 schedule 直接调用,但接口签名兼容) |

## 五、摩擦记录

| # | 描述 | 类型 | 处理 |
|---|---|---|---|
| 1 | `WeekRangeParser` 先 split 再剥 `周` 后缀导致跳跃周次 `"1-8,10-17周"` 最后一段匹配失败 | 实现 bug | 改为 split 后逐段清 `周` 后缀 |
| 2 | `ScheduleListExtractor` 从 `roomText` 拆课程名(错误字段) | 实现 bug | 改为从 JS 抓到的 `courseName` 提取,`roomText` 只拆周次 |
| 3 | `BookingStep` 不是函数式接口,lambda 语法不兼容 | API 误用 | StubStep 改为匿名类 |
| 4 | `VenueCommand`/`HomeworkListCommand` 原有 human format 与 `CommandOutput` 通用实现不兼容 | 重构冲突 | 每个 command 保留自己的 human format,只共享 JSON path |
| 5 | `EhallScheduleClient` 只 catch `BookingException`,其他异常(如 `RuntimeException`) 穿透 | 遗漏 | 加 `catch (Exception e)` 兜底 |
| 6 | `HomeworkListCommandTest` / `VenueCommandTest` 调用已删的 `VenueCommand.exitCodeFor` | 遗留引用 | 批量 sed 替换为 `CommandOutput.exitCodeFor` |
| 7 | CAS 登录 `landed on ehall: false` → 真实账号联调失败(密码待确认) | 外部依赖 | 标记 ⏸️ ,待用户确认正确密码后重新执行 |
